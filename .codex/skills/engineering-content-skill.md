# Engineering Content Skill

## Purpose
This skill defines how technical project content should be written for the portfolio website.

## Core Principle
Write about engineering judgment, not just tools.

A weak statement:

> Used I2C, SPI, UART, BLE, and MQTT.

A stronger statement:

> Designed sensor and communication architecture across low-power embedded nodes, RF links, and gateway interfaces, balancing battery life, payload size, field reliability, and maintainability.

## Content Hierarchy
Prioritize:

1. Problem
2. Constraints
3. Architecture
4. Trade-offs
5. Testing
6. Field reality
7. Outcome
8. Lessons learned

Tools and technologies are supporting evidence, not the main story.

## Case Study Writing Pattern
Use this structure:

```text
Summary
Problem
Operating Context
System Architecture
Key Engineering Decisions
Implementation
Validation
Field / Deployment Reality
Outcome
Lessons Learned
What This Demonstrates
```

## Confidentiality Filter
Before writing any project content, ask:

- Is this information public?
- Could this reveal company IP?
- Could this expose a client, commercial detail, or product weakness?
- Can the same point be made at architecture level instead?

When uncertain, generalize.

## Good Engineering Themes
Use these themes where relevant:

- Real-world survival
- Harsh environments
- Reliability over elegance
- Trade-offs under constraints
- Field deployment feedback loops
- Hardware-firmware-system integration
- Manufacturing awareness
- Productization beyond prototype
- Technical leadership through ambiguity

## Avoid
- Overclaiming ownership
- Excessive acronyms
- Pure task lists
- Weak resume verbs
- Confidential data
- Unverified metrics
- Hype language

## Preferred Language
Use wording like:

- Designed
- Architected
- Validated
- Integrated
- Diagnosed
- Led
- Recovered
- Productized
- De-risked
- Field-tested
- Simplified

## Content Reuse
Every project page should produce reusable material for:

- Resume bullets
- LinkedIn posts
- Interview stories
- GitHub README sections
- Consulting capability statements
